# Redraw inventory: goal page and PI deck figures, 2026-11-06

**Request (Priya 11-06, via the PI-deck window).** Once the SVG branch (`feat/svg-page-figures-20261106`) is on main, we
want SVGs of the current figures by redrawing them from stored outputs. For each figure this inventory gives:
- (a) the drawing script and its flags;
- (b) whether the figure can be redrawn from stored outputs without refitting, and which stored files that reads;
- (c) what a redraw still recomputes, with rough wall time and peak RAM;
- (d) which figures have no redraw-only path.

**Inventory only.** Nothing was run, re-rendered or killed. The work was code reading, render-log reading and listing
small folders on M:.

**Drawing script.** This is the provenance table's `producing_script`, corrected in three ways:
- **Stem found in code.** When the PNG stem appears literally in exactly one characterised script, that script is
  used (36 rows).
- **Catch-all entries.** The provenance map files about 60 lick / recovery / disengagement figures under
  `lick_balance_subsets`. They are mapped to their real drawers by stem prefix (`rec_wlc_` -> within_lick_correction,
  `dis_` -> disengagement_tests, `sm_` / `cv_` -> coupling_vigour_sm, `xa_` / `ihf_` -> interhemi_crossarea, ...).
- **Deck pictures** use the page figure their note names. Deck-only pictures use the script the note names, read by
  helper 5.

**Redraw path (code).** This describes what the code allows, not what is on disk.

| path | meaning |
|---|---|
| **yes** | A pure redraw mode exists, such as `--plot-only`. It goes through `scripts/figdata.py` (`<iti_licks OUT>/figdata/<stem>.pkl`) or `rebuild_figs/_common.load_figdata` (`<out>/data/<name>_figdata.pkl`). Other forms: `iti_licks --plot-only --key` (key_figures_plot), `--reuse*`, `--from-csv`, or `lmm_hidden.render.redraw`. It refits nothing, bootstraps nothing and loads no imaging; about 0.5-2 min, mostly imports. |
| **partial** | No model is refit, but a redraw recomputes something real: nested bootstraps or permutation nulls, statsmodels LMMs on stored tables, a re-collection of per-session json / npz, or imaging loads. Also partial: plot-only covers only some of the script's figures. |
| **no** | The figure is only reachable through the full analysis. |

**Inputs in _daqlk now.** This column says whether the stored files a redraw needs exist now, for the `_daqlk` render.
- At 13:57, 70 of the page's mapped render steps were done, 4 running, 3 failed and 338 pending.
- The `_daqlk` iti_licks figdata folder holds only 22 pickles. These are the `lick_matched_*` plain variants, the
  `iti_licks --key`, `--controls` and `--ramp` families, the where_scatter non-z pickles, fr_lick_variance and
  covref_offset.
- So most "yes" figures can be redrawn only after their pending `_daqlk` step has written its pickle or CSV.
- **If the SVG branch is merged into the render worktree before a pending step runs, that step emits its SVG directly
  and needs no redraw.** The render runs pinned code (`wf_render_v8f` @ 110c4efd). That is the cheapest path for the
  ~300 pending-step figures.

**Times and RAM.** Estimates for 1-2 workers come from:
- the `# start` / `# end` headers of `render_daqlk/logs/<step>.log` (82 steps);
- the older `scratchpad/logs` (START / END epochs);
- code reading.

The logs record no peak RAM, so the GB figures are estimates from what each redraw loads.
