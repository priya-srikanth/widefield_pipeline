## Bugs found in the last two days — all silent, all now guarded

Each of these produced plausible numbers rather than an error. That is the pattern to watch for.

1. **Six analysis modules hardcoded the zerophase `SVTcorr`.** Adopting a new variant would have
   changed nothing while appearing to. → `config.svtcorr_path()` / `svtcorr_in()`, one config key, plus
   a test that fails if the literal returns.
2. **`CACHE_VERSION` doesn't see config changes.** Cached decode/encode/RDM results would have been
   served from zerophase data under the new methodology. → bumped at each flip (5, then 6).
3. **The production decoder could not sub-bin at all.** The adopted 4×0.5 / 8×0.25 arms lived only in
   a research harness, so no deck used them. → `_window_feature`, with baseline and region labels
   tiled (both would have been silently wrong).
4. **Rendered maps do not re-render on a config flip.** Every date before 8/13 still showed the filter
   shadow — pre-cue map = NEGATIVE of the post-cue map, r = −0.93 on the worst sessions — while the
   decoders had moved. → all dates re-rendered; maps record `svtcorr` provenance; `build_deck`
   EXCLUDES sessions whose maps are off-variant and names them.
5. **`load()` returned a stale joint basis.** `basis_id` distinguishes bases on disk but does not stop
   an old one being loaded; all four predated the flip, so the joint slides described superseded data.
   → `basis_is_current()` + a loud warning.
6. **The deck still warned "PRE-CUE numbers are inflated ~2×"** — an entire slide plus three titles,
   after the numbers had been corrected. A stale warning is worse than none. → replaced; guard test.
7. **`fig_top_components` was broken for all 44 sessions** — sub-binned feature indices used to index
   the component axis. → footprint figures pin `bins=1`.
8. **PS95 8/13: 23% of trials had no imaging and were decoded anyway.** The repair correctly dropped
   the 32-min single-channel prefix, but `_nearest_corrected_frame` CLIPS, so 197 of 871 cues mapped
   to frame ~0. Cue-aligned 0.61 vs ~0.90. → `coverage_mask` in both the analysis and event-map paths;
   the exclusion prints its count.

9. **`CACHE_VERSION` was not bumped when the coverage fix landed** (found 17 Aug). `_frames` is
   inside the cached compute path for all four kinds, so the run launched to VERIFY the fix would
   have served PS95 8/13 its pre-fix cross-session numbers, while the uncached per-date figures
   recomputed correctly — the two would have disagreed and nothing would have said so. → v7, and
   the v6 cache is snapshotted so the "no-op for the other 43 sessions" claim is checked, not
   assumed. Third instance of this exact pattern (see the v5/v6 notes).
10. **The no-lick arm's null was 1/6, which it never was** (found 17 Aug, answering Priya's
    post-stroke question). Those trials are heavily skewed across positions (PS93: 49% far_center)
    and the decoder's predictions on them are skewed too, so an information-free decoder scores
    0.211 on PS93, and a constant "always guess far_center" scores 0.490 — beating the decoder's
    own 0.293. The wrong null produced BOTH a "carries no position code" finding in DECISIONS.md
    *and*, later, an "above chance" flag for all four animals; the same comparison was
    uninformative in both directions. → `nolick_analysis`: balanced accuracy (null expectation
    exactly 1/6 however skewed either side is), permutation null on these trials, matched
    subsample. The retired claim lived in FOUR places — DECISIONS.md, the `ood_control` docstring,
    the deck's speaker notes, and a rendered FIGURE TITLE.

11. **My per-session response-window lookup read the wrong session's config.** It globbed
    `{animal}_*` when it could not resolve a date and took the first match, so every session read
    its animal's EARLIEST `gui_config.json`. All 44 curated sessions reported a 3.0 s response
    window when the files plainly say 3500 ms. → the date now comes from the session's own DAQ
    path, and an unresolvable one raises instead of borrowing a neighbour's config.
12. **A fresh build and a re-read disagreed about their own output.** `direction_consistency` was

13. **The v6/v7 cache diff cried wolf on 10 sessions.** Scalar floats went through `==` after

    clustered in `hemi`/`crossnobis` and never touched `per_session` outside 8/13. A real coverage
    bug could not have had that shape. → NaN normalised; the diff then came back **172 identical,

14. **The agreement figure drew CUTS as though they were animals.** Nesting `consensus` by cut left
    `figure_agreement` iterating it as `{animal: verdict}`. It did not crash: it rendered two rows
    labelled "2.0s" and "respwin" with empty disagreement strings, and the deck reported 441 figures
    and **0 missing**. The deck checks that figures EXIST and the tests check that code RUNS; nothing
    asserts what a figure SAYS, and every wrong-figure bug here has gone through that gap.
    → `normalize_consensus` validates the shape at the figure boundary and RAISES on an unrecognised
    one, converting the class from "renders nonsense" to "stops" — the only part a test can reach.

15. **The rolling decoder kept all 197 uncovered PS95 8/13 cues** (found 17 Aug by Priya reading
    slide 15: "the numbers still look too low"). `_frames` marked them -1 correctly; `_engaged` and

16. **My `nolick_decoder` collapsed duplicate region labels.** Joint bases map several components to

17. **`_align_many` did the same thing in PRODUCTION, and had since 2026-08-14** (found by Priya:
    the ROI frozen decoders "perform much worse than the single-session decoders"). Sub-binning
    tiles the region vector once per bin -- 66 areas x 4 bins = 264 columns, 64 distinct labels --
    so the 4 x 0.5 s time course became four copies of bin 0 in EVERY ROI frozen number. Post-cue
    was understated by 0.23-0.41 (PS92 0.485 -> 0.890); pre-cue barely moved, which is the mechanism
    confirming itself. Transfer cost stays positive, so the conclusion held and only the magnitudes
    were wrong. → key on (label, occurrence); 5 regression tests, verified RED against the old code.

**Bugs 15-17 were all found by a person reading the deck, and none of them could have been caught by
anything in the pipeline.** 17 in particular: the shapes were right, the counts were right, 264
features went in and 264 came out. The two independent occurrences of one wrong idea -- match
features by LABEL, resolve with `.index()` -- are why it now has a test rather than two fixed lines.

**FIVE of the first fourteen were checks I wrote, not faults in the pipeline** (map provenance → all 57 sessions
"stale"; basis currency → all four fresh bases "stale"; the cache diff → 10 phantom sessions; plus
12 and 11 above). A guard's characteristic failure is the FALSE ALARM, and the diagnostic is the
SHAPE of the false positives, not their count: everything failing at once, or failing in a pattern
no real fault could produce (only `hemi`, never `per_session`; every session reporting the same
wrong number). **Check a new guard against a known-GOOD case, not only a known-bad one — and when
it fires broadly, suspect the guard first.**

**A claim lives in more places than the code that computes it.** #6 (the "inflated ~2×" warning) and
#10 both outlived their numbers in prose — speaker notes, a decisions doc, a figure title. When a
finding changes, grep for it; the computation is the easy half.

## The no-detected-lick arm (new 17 Aug — the pre-stroke reference for post-stroke failures)

Post-stroke a failed trial can mean the plan was never formed, or that it was formed and the movement
failed. Identical in the behaviour log; opposite predictions here — plan-intact keeps the PRE-cue code
while the POST-cue code collapses, because post-cue decoding is largely driven by the lick itself.

**Modules.** `nolick_analysis` (pure statistics, 30 tests) · `nolick_decoder` (per session, per
animal, cross-session) · `plot_nolick_reference`. Frozen to
`E:/cue_lick/nolick_reference_prestroke.json`.

**The statistics, and why the obvious version is wrong.** The old arm judged accuracy against a
uniform 1/6. These trials are heavily skewed across positions (PS93: 49% far_center) AND the
decoder's predictions on them are skewed, so an information-free decoder scores 0.211 on PS93, and a
constant "always guess far_center" scores 0.490 — above the 0.293 measured. Headline is now BALANCED
accuracy, whose null expectation is exactly 1/6 however skewed either side is; raw accuracy is judged
against a permutation null computed on these trials; a position-matched subsample is the independent
check. The test is ONE-SIDED (directional hypothesis); the two-sided interval is kept but labelled
DESCRIPTIVE, because at the margin the two disagree.

**The grid.** TWO bases (Allen-ROI, joint-LocaNMF with sessions projected and never refitted) × TWO
engaged cuts (the decoder's 2.0 s, and the task's own response window) × both alignments, per animal
and per session.

**Categories, all bounded by the response window** — nothing is analysed past it, because the spout
starts moving when it closes (Priya, 17 Aug):

```
engaged        lick within the cut
late_rewarded  lick after the cut but within the response window — a HIT the decoder discards
undetected     no detected lick within the window   (split further, below)
```

**Two splits that changed the conclusion.**

* `late_rewarded` vs `undetected`: on PS93 8/12 the pre-cue survival is carried ENTIRELY by late
  trials (balanced 0.532, p=0.003) while undetected trials show nothing (0.153, p=0.76).
* `undetected_working` vs `undetected_disengaged`, reusing the pipeline's `flag_engagement`: a miss inside
  a working stretch is a candidate "tried and fell short"; a miss in the satiation tail is "stopped
  working" (Priya, 17 Aug). PS95 8/14 has 39 of 57 undetected trials in a terminal run (trials
  563–632 of 633); PS93 8/12 has 36 of 39 inside working stretches. Opposite composition, same
  pooled label.

**Results.** The direction is robust: pre-cue survival exceeds post-cue in **16/16** animal × basis ×
cut comparisons, ratios 1.1–3.5×. Significance (paired session bootstrap, one-sided) is not: at the
2.0 s cut PS93 and PS95 in both bases, PS94 in joint only (p=0.037, marginal); at the
response-window cut **PS95 alone**. The mechanism is legible — moving the cut reclassifies the
late-but-successful trials as engaged, removing exactly the trials that carry the pre-cue signal.

**"No detected lick" is not "no attempt."** The sensor needs contact. PS93 has a pre-existing
rightward tongue bias and reaches far_L poorly, so its far-position undetected trials are
substantially attempted-and-short — making **PS93 far_L a pre-stroke, within-subject instance of the
post-stroke phenotype**, with ground truth owing nothing to the stroke. `ATTEMPT_CONFOUNDED` is the
DLC/facial-tracking target list.

**Pre- vs post-stroke criteria (Priya, 17 Aug).** Pre-stroke uses lick-restricted trials; post-stroke
will need ALL trials, because a missing detection may be a tongue protrusion that fell short. Both
traps are real, and `nolick_analysis.assert_comparable` RAISES on a mismatch: engaged-only-pre vs
all-trials-post scores lower with no stroke required, and post-stroke "engaged" is
SURVIVORSHIP-selected toward preserved function. Compute every criterion; compare like with like.
`reference_position_engagement` implements the close_L/close_center motivation control,
parameterised because which positions are spared is a phenotype question.

## Lick BOUT ONSETS (new 17 Aug)

The lick-aligned decoder uses ONE lick per trial and discards 80–93% of lick events.
`lick_bout_events` + `lick_bout_decoder` use bout ONSETS (movement initiations) instead — 1.16–4.24
per trial, honest rather than inflated, because bouts collapse the correlated 5–7 Hz licks.

* Labelled by the SPOUT STROBE, not the preceding cue. The old cue rule gives arrival-window licks
  the PREVIOUS trial's position; ~6-trial blocks hide it, so the genuinely mislabelled fraction is
  PS93 7.3%, PS94 5.0%, PS95 0.8%, concentrated at block transitions.
* Eligible interval `[strobe, cue + response_window]`; bouts whose FEATURE window would overrun are
  dropped and counted.
* CV groups are TRIALS. Bouts share a trial; grouping by bout would leak, and would inflate accuracy
  in proportion to the apparent gain — where it is least visible and most flattering.
* Phases scored separately (`approach` pre-cue vs `response`) — PS92 is 74% approach, PS95 6%.

**Read the approach result correctly.** PS92 8/12 approach bouts decode at 0.761 balanced (n=704 over
172 trials, p=0.003) — but the animal is LICKING THE SPOUT, so position is available
somatosensorily. That is a motor/sensory readout, NOT a pre-cue plan, and must not be quoted as one.
Its value is a 4× larger movement-locked reference for the post-stroke arm.

## Cautions

* **A config flip reaches computation instantly and rendered artifacts not at all.** Anything already
  on disk needs re-rendering, and needs provenance so nobody has to remember.
* **Chain long jobs; never fire-and-forget.** On 8/14 staging finished at 00:15 and nothing picked it
  up until 07:19 — 7 idle hours — because a waiter was armed for the uploads but not for the work they
  unblocked.
* **Pipe background jobs to a file, not through `grep`** without `--line-buffered`. Cost a log twice.
* **Run the test suite as its own gate**, not as a neighbour of the commit — a `&&` chain starting at
  `git add` will push with failing tests.
* **Verify against the artifact, not the script's success message.** A partial string replacement
  printed "done" while leaving the file wrong, and the same regen failed twice.
* **`archive_day clean` will delete raw that was STAGED for imminent use** (it is archived by
  definition). Guarded now, but check what a clean proposes before executing it.
