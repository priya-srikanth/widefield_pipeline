## Bugs found in the last two days — all silent, all now guarded

Each of these produced plausible numbers rather than an error. That is the pattern to watch for.

1. **Six analysis modules hardcoded the zerophase `SVTcorr`.** Adopting a new variant would have
   changed nothing while appearing to. → `config.svtcorr_path()` / `svtcorr_in()`, one config key, plus
   a test that fails if the literal returns.
2. **`CACHE_VERSION` doesn't see config changes.** Cached decode/encode/RDM results would have been
   served from zerophase data under the new methodology. → bumped at each flip (5, then 6).
3. **The production decoder could not sub-bin at all.** The adopted 4×0.5 / 8×0.25 arms lived only in
   a research harness, so no deck used them. → `_window_feature`, with baseline and region labels
   tiled (both would have been silently wrong).
4. **Rendered maps do not re-render on a config flip.** Every date before 8/13 still showed the filter
   shadow — pre-cue map = NEGATIVE of the post-cue map, r = −0.93 on the worst sessions — while the
   decoders had moved. → all dates re-rendered; maps record `svtcorr` provenance; `build_deck`
   EXCLUDES sessions whose maps are off-variant and names them.
5. **`load()` returned a stale joint basis.** `basis_id` distinguishes bases on disk but does not stop
   an old one being loaded; all four predated the flip, so the joint slides described superseded data.
   → `basis_is_current()` + a loud warning.
6. **The deck still warned "PRE-CUE numbers are inflated ~2×"** — an entire slide plus three titles,
   after the numbers had been corrected. A stale warning is worse than none. → replaced; guard test.
7. **`fig_top_components` was broken for all 44 sessions** — sub-binned feature indices used to index
   the component axis. → footprint figures pin `bins=1`.
8. **PS95 8/13: 23% of trials had no imaging and were decoded anyway.** The repair correctly dropped
   the 32-min single-channel prefix, but `_nearest_corrected_frame` CLIPS, so 197 of 871 cues mapped
   to frame ~0. Cue-aligned 0.61 vs ~0.90. → `coverage_mask` in both the analysis and event-map paths;
   the exclusion prints its count.

9. **`CACHE_VERSION` was not bumped when the coverage fix landed** (found 17 Aug). `_frames` is
   inside the cached compute path for all four kinds, so the run launched to VERIFY the fix would
   have served PS95 8/13 its pre-fix cross-session numbers, while the uncached per-date figures
   recomputed correctly — the two would have disagreed and nothing would have said so. → v7, and
   the v6 cache is snapshotted so the "no-op for the other 43 sessions" claim is checked, not
   assumed. Third instance of this exact pattern (see the v5/v6 notes).
10. **The no-lick arm's null was 1/6, which it never was** (found 17 Aug, answering Priya's
    post-stroke question). Those trials are heavily skewed across positions (PS93: 49% far_center)
    and the decoder's predictions on them are skewed too, so an information-free decoder scores
    0.211 on PS93, and a constant "always guess far_center" scores 0.490 — beating the decoder's
    own 0.293. The wrong null produced BOTH a "carries no position code" finding in DECISIONS.md
    *and*, later, an "above chance" flag for all four animals; the same comparison was
    uninformative in both directions. → `nolick_analysis`: balanced accuracy (null expectation
    exactly 1/6 however skewed either side is), permutation null on these trials, matched
    subsample. The retired claim lived in FOUR places — DECISIONS.md, the `ood_control` docstring,
    the deck's speaker notes, and a rendered FIGURE TITLE.

**Two guards I wrote were themselves broken and flagged everything** (map provenance read the wrong
summary → all 57 sessions "stale"; basis currency recomputed the wrong rank → all four fresh bases
"stale"). A guard that fires on everything is ignored. **Check a new guard against a known-GOOD case,
not only a known-bad one.**

**A claim lives in more places than the code that computes it.** #6 (the "inflated ~2×" warning) and
#10 both outlived their numbers in prose — speaker notes, a decisions doc, a figure title. When a
finding changes, grep for it; the computation is the easy half.

## The no-detected-lick arm (new 17 Aug — for the FIRST POST-STROKE SESSION, today)

Post-stroke a failed trial can mean the plan was never formed, or that it was formed and the movement
failed. Identical in the behaviour log; opposite predictions here — plan-intact keeps the PRE-cue code
while the POST-cue code collapses, because post-cue decoding is largely driven by the lick itself.

* `nolick_analysis` — the statistics (balanced accuracy, permutation null on the arm, matched
  subsample, survival ratio, `interpret()`); pure, 12 tests.
* `nolick_decoder` — per session, per animal, cross-session; runs in BOTH poolable bases (Allen-ROI
  and joint-LocaNMF, sessions PROJECTED never refitted) and emits a per-animal `consensus`, with an
  explicit `DISAGREEMENT` record when the bases differ.
* THREE arms, not two: `engaged` (lick ≤ 2 s) / `late` (2–5 s) / `undetected`. The old pooled arm
  hid the distinction — on PS93 8/12 the pre-cue survival is carried ENTIRELY by late trials
  (balanced 0.532, p=0.003) while undetected trials show nothing (0.153, p=0.76).
* **"No detected lick" is not "no attempt."** The sensor needs contact. PS93 has a pre-existing
  rightward tongue bias and reaches far_L poorly (Priya, 17 Aug), so its far-position undetected
  trials are substantially attempted-and-short — which makes **PS93 far_L a pre-stroke,
  within-subject instance of the post-stroke phenotype**, with ground truth owing nothing to the
  stroke. `ATTEMPT_CONFOUNDED` is the DLC/facial-tracking target list.
* The pre-stroke reference is frozen ONCE to `nolick_reference_prestroke.json` and never
  overwritten. A reference that moves after the comparison data arrive is not a reference.

## Cautions

* **A config flip reaches computation instantly and rendered artifacts not at all.** Anything already
  on disk needs re-rendering, and needs provenance so nobody has to remember.
* **Chain long jobs; never fire-and-forget.** On 8/14 staging finished at 00:15 and nothing picked it
  up until 07:19 — 7 idle hours — because a waiter was armed for the uploads but not for the work they
  unblocked.
* **Pipe background jobs to a file, not through `grep`** without `--line-buffered`. Cost a log twice.
* **Run the test suite as its own gate**, not as a neighbour of the commit — a `&&` chain starting at
  `git add` will push with failing tests.
* **Verify against the artifact, not the script's success message.** A partial string replacement
  printed "done" while leaving the file wrong, and the same regen failed twice.
* **`archive_day clean` will delete raw that was STAGED for imminent use** (it is archived by
  definition). Guarded now, but check what a clean proposes before executing it.
