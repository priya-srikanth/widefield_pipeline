## The headline finding

**`wfield.hemodynamic_correction` removes drift with a ZERO-PHASE (acausal) 0.1 Hz filter, and the
filtered channel becomes `SVTcorr`.** A zero-phase filter's impulse response is symmetric in time
(measured on this filter: −0.496 before an impulse, −0.496 after), so each position-specific POST-cue
response casts a sign-flipped shadow BACKWARDS into the pre-cue window. A decoder does not care about
sign, so that shadow read as pre-cue position information.

**This is the upstream Churchland/wfield method, not a local bug**, and the artifact class is published
(van Driel, Olivers & Fahrenfort 2021, *J Neurosci Methods*). Our exposure is worse than theirs because
we DECODE a condition label from a window PRECEDING the condition-specific response; their headline
analyses are encoding models with lagged regressors that absorb the distortion into the fitted kernel.

**ADOPTED FIX: `meegkit_hpfit`, polynomial order 10.** Keep the 0.1 Hz high-pass for the COEFFICIENT
FIT (that is what it is for — `rcoeffs` is one scalar per pixel and needs the hemodynamic band to
dominate the fit), and replace it for the OUTPUT with de Cheveigné robust polynomial detrending on a
mask that excludes the whole trial. 36 curated sessions: pre-cue 0.486 → 0.352, **post-cue 0.684 →
0.759** (better), shadow signature gone (negative pre/post correlation in 30/36 → 2/36).

**What survives:** pre-cue position information is real, significant in **35/36 sessions**, at ~72% of
the published effect. PS92 0.225, PS93 0.349, PS94 **0.500**, PS95 0.334 (chance 0.167, empirical null
0.137–0.147). PS94 essentially untouched; PS92 the one substantially inflated.

**Terminology changed** to "pre-cue position information", not "maintained motor plan" — the spout
arrives ~3 s before the cue, so a sustained sensory response and a held intention are temporally
coextensive and this design cannot separate them. It does not need to: a pre-cue position signal that
changes post-stroke is the readout either way.

## Other findings, 13–14 Aug

**Decoder windows and alignment** (`DECISIONS.md` has the tables):
* **Do NOT extend the cue window to 3 s.** PS94/PS95 decline monotonically; PS93 far_L — the
  motivation — does not improve at any length. `cue_post_s` stays 2.0.
* **Lick alignment beats cue alignment in 4/4 animals** (PS92 +0.075, PS93 +0.071, PS94 +0.016,
  PS95 +0.032), and recovers PS93 far_L from 0.436 → 0.556. The limiting factor is RT VARIABILITY, not
  RT magnitude — a jittered response smears under cue alignment and a longer window adds noise without
  unsmearing it.
* **Pre-cue: 4 × 0.5 s sub-bins beat the 2 s mean** (+0.032, 14/16) on corrected data — the reverse of
  what the artifact-laden data showed. 8 × 0.25 s is worse; 250 ms over-slices.
* **Pre-lick instead of pre-cue: NO** — RT differs by position (0.128–0.384 s), so a pre-lick window
  admits a position-dependent slice of the post-cue response and would partly decode reaction time. As
  an ADDITIONAL movement-preparation analysis: yes, with RT matched or regressed out.

**Joint basis:** `variance_captured` is NOT a sufficient health check — 8/12 reads 98.9–99.4% while
carrying a −0.079 mean projection penalty (PS92 −0.172). Every post-stroke session will be a projected
day, so that cost must be calibrated on held-out pre-stroke days, or Allen-ROI used as the primary
readout since it involves no projection.

## WHAT CHANGED ON 14 AUG (after the first handoff was written)

**The adopted methodology is now actually in force.** It was not before, in three separate ways, each
of which failed silently rather than loudly:

1. **Six analysis modules hardcoded `wfield_local_results/SVTcorr.npy`** — the ZEROPHASE file — so
   LocaNMF and every decoder would have kept reading superseded data with no error and no missing
   file. Now `config.svtcorr_path()` / `config.svtcorr_in()`, driven by `defaults.yaml hemo.variant`,
   with a guard test that fails if the literal reappears. The maps chain (4 more modules) reads the
   same variant, per Priya: **meegkit_hpfit for everything**.
2. **`CACHE_VERSION` 4 → 5.** The cache keys on input mtimes, which do NOT see a config change, so
   every cached decode/encode/RDM would have been served from zerophase-derived results under the new
   methodology, indistinguishable from a real re-run.
3. **The production decoder could not sub-bin at all.** The adopted 4×0.5 / 8×0.25 arms lived only in
   `precue_window_sweep.ARMS`, a research harness; `locanmf_position_decoder` built one window mean.
   Now `_window_feature`, with `defaults.yaml decode.bins` (precue 4, cue 4, lick 8). Baseline and
   component→region labels are tiled with the features — both would otherwise be wrong silently.

`preprocess` now BUILDS the variant itself (step 3b) so it can no longer be forgotten per session, and
`hemo_variants` takes `--mc/--h5/--label` so an unregistered night works before `sessions.yaml` is
edited.

**Post-cue / post-lick sub-binning result** (16 sessions, both predictions I stated beforehand were
wrong): sub-binning helps LESS post-event (+0.020 cue, +0.023 lick) than pre-cue (+0.032), and 0.25 s
bins win post-lick where they LOST pre-cue. The keeper is the asymmetry reversal — post-cue
`last1.0−first1.0` = **+0.089** (information accumulating after the cue), post-lick **−0.030**
(already maximal at lick onset and decaying), which is what movement-locked information should look
like. Full table in `DECISIONS.md`.

**Sessions done:** PS94 and PS95 8/13 fully preprocessed, variants built, registered, maps rebuilt on
the variant. PS95 required the single-channel repair first (206,391 pairs; alignment verified from the
camlog AND the pixels, 1.000 at offset 0). PS94 raw+bin archived to standby and cleaned locally.

**Two extreme sessions worth remembering:** PS94 8/13 is 1.3% quiet (2,488 quiet vs 13,245 running
frames); PS95 8/13 is the near mirror image (14,326 quiet vs 571 running). Quiet-baseline comparisons
between them are not like-for-like.

### Later on 14 Aug — data-safety and reporting

* **HARD RULE, now enforced in code (CLAUDE.md rule 0).** `writeguard.assert_deletable` refuses to
  delete ACQUIRED data (`.dat`, `.h5`, `.camlog`, `.avi`, `trials.csv`/`events.csv`/`gui_config.json`)
  unless a server copy has been CONFIRMED, or the caller declares `derived=True` (reproducible from
  archived inputs) or `approved=True` (explicit permission). Wired into `archive_day`'s delete sites.
  A `.sha256` sidecar is a CLAIM about a file, not a measurement of the archived bytes.
* **`archive_day` learned two things by being run for real.** It would have deleted PS92's raw and DAQ
  `.h5` minutes after a 41-minute stage, because staged-from-archive data is archived by definition —
  a session is now "spent" only once its SVD output exists. And a repaired `.dat` is an INTERMEDIATE,
  not raw: it would otherwise have been filed on standby beside the genuine original under a name that
  looks like an acquisition.
* **Camlogs are now mirrored to standby.** They were classified as outputs and landed only on
  MICROSCOPE — a single copy of an acquisition record, and the file that independently verified PS95
  8/13's frame alignment.
* **The encoder is pinned to `bins=1` explicitly.** It builds features through the decoder's
  `_trial_features` with no `bins` in its namespace, so adopting sub-binning would have silently made
  it a model of each component's 8-bin TIME COURSE instead of its mean activity, changing what R², EV
  and the FEVE ceiling mean. Sub-binning is measured for DECODING only. **Open question for Priya:**
  test the sub-binned encoder (EV at 1 vs 4 vs 8 bins) or leave it on the mean.
* **PS92 8/12 concat.** `events.csv` is now merged too (`concat_behavior_events`), which restored
  first-lick latency — log-derived medians agree with DAQ-derived to 5–20 ms. The DAQ stays the
  DEFAULT trial source per Priya; `load_trials` now WARNS when the DAQ holds <90% of the log's scored
  trials, which is the case that let a 225-trial figure pass as "concat". Trial accounting corrected:
  283 trials / 280 scored, not "563" (that was rows, ~2 per trial).
* **Deck notes rewritten.** `M_PRECUE_CAVEAT` had gone stale-and-wrong ("inflated … not yet
  recomputed"); it now describes the corrected state. `M_COMMON` names the variant used by every panel
  including maps; `M_DECODE` describes sub-binned features.
* **`EXPERIMENT_ERRORS.md` audited** — added the dead `spout_bit1` (8/5–8/6, all four animals), PS93
  8/5's empty log recovered from cam1, and the 8/13 quiet/running imbalance (PS92 has 255 quiet frames
  ≈ 8 s, so its quiet map is not quantitative).

  "figures placed / missing" line regardless.
* ~~Never run `python -m wfield_local.preprocess_deck`~~ — **OBSOLETE, verified 2026-08-14.** The prune

  each delete through `writeguard.assert_writable`. Both branches are tested. Safe to use — and keeping
  the ban had a cost: the 14 Aug deck rebuild was hand-rolled per animal for no reason.
* **Pipe background jobs to a file, not through `grep`** without `--line-buffered`: output buffers and
  the job looks dead. This cost a nearly-complete job earlier.
* **Do not tune a window or parameter on the outcome it is judged by.** The 60 s detrend window sat
  exactly on the position-block timescale (57–121 s) and removed the most signal of any setting tested;
  the "code builds toward the cue" asymmetry (+0.246) was the filter shadow and vanished (−0.040) once
  corrected.
* **A claim asserted before it is tested is the recurring failure mode here.** Six corrections in two
  days, most surfaced by Priya's questions rather than by my own checks. Test first, then write it down.
